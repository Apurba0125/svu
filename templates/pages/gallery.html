HOW THE VIEWER IS WIRED data-viewer on a grid makes it one gallery; data-viewer-item on each cell makes it a frame. That is the whole contract — no onclick attributes and no index numbers to keep in step, so inserting a photograph in the middle does not renumber anything after it. The viewer (counter, fullscreen, close, arrows, caption, keyboard, swipe) is built by main.js and styled in base.css, shared by every gallery page. Each section has its OWN data-viewer name, so the arrows and the counter stay inside that event. Give a new section a new name; reusing one merges the two grids into a single run of photographs, which is almost never what you want. The caption under an enlarged photograph is that image's own alt text, so writing a good alt does double duty. TO ADD A PHOTOGRAPH 1. Put the file in static/img/Gallery/ 2. Copy one "gallery cell" block into the right section and change the src and the alt 3. Run: python manage.py collectstatic --noinput Not optional — a static path with no manifest entry raises ValueError on every request, so the page goes down rather than showing a broken image. Cells are a fixed height and the photograph is cropped to fill, so portrait, landscape and square originals all come out identical in the grid. The enlarged view shows the whole uncropped photograph. Rows are four across, so a count that is a multiple of four never leaves an orphan tile at the end of a section on a wide screen. The first cell in each section deliberately has no loading="lazy" — it is above the fold often enough that deferring it just delays the first paint. NOTES ON THE FILES THEMSELVES .jfif is an ordinary JPEG with an unusual extension, and Python maps it to image/jpeg, so it serves correctly. No need to rename them for that reason. "CU14 (1).jpg" in static/img/Gallery/ is byte-for-byte identical to "CU14.jpg" — only CU14.jpg is used here. Delete the copy when convenient. The 48…/53…/54…_n.jpg.jpeg names in the first section are Facebook's own: that is what the CDN calls an image, and the doubled extension is what the browser saved. They are the university's own photographs, so there is no provenance problem, but the names carry no meaning. Several of the fest photographs are 4704x3136 at half a megabyte or more. They are served full size and only then scaled down by the browser. Resizing the originals to about 1600px wide would cut most of this page's weight without any visible difference in the grid or the viewer.
