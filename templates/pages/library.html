Nothing else to wire up. HOW THE VIEWER IS WIRED data-viewer on the grid makes it one gallery; data-viewer-item on each cell makes it a frame. That is the whole contract — no onclick attributes and no index numbers to keep in step, so inserting a photograph in the middle does not renumber anything after it. The viewer itself (counter, fullscreen, close, arrows, caption, keyboard, swipe) is built by main.js and styled in base.css, shared by every gallery page. The caption under the enlarged photograph is the image's own alt text, so writing a good alt does double duty and there is no second list of titles to fall out of sync with the images. TO ADD A PHOTOGRAPH 1. Put the file in static/img/library/ 2. Copy one "gallery cell" block and change the src and the alt 3. Run: python manage.py collectstatic --noinput Not optional — a static path with no manifest entry raises ValueError on every request, so the page goes down rather than showing a broken image. Cells are a fixed height and the photograph is cropped to fill, so portrait, landscape and square originals all come out identical in the grid. The enlarged view shows the whole uncropped photograph. Only two library photographs are in the repository so far, so the grid is seeded with those two. NOTE ON COMMENTS: the hash-style Django comment covers a SINGLE line only.
